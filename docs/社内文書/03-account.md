# アカウント発行・停止基準
文書番号：情基-SEC-008　版数：第4版　施行日：2026年6月15日
主管部署：情報システム部・人事部

## 1. 基本方針
会社アカウントは本人確認と業務上の必要性に基づき発行する。アカウントの種類は、通常社員、契約社員・派遣社員、外部委託先、共有用途の4区分とする。共有用途アカウントは例外扱いであり、情報システム部長の事前承認が必要である。アカウント発行の申請者は原則として所属上長とし、本人からの直接申請だけでは発行しない。

## 2. 通常社員の発行
人事システムに入社情報が登録され、所属部署、上長、雇用開始日が確定した後、上長が入社日の5営業日前までに申請する。情報システム部は本人確認と申請内容を確認し、原則として入社日の前営業日までにアカウントを準備する。アカウントの有効化は雇用開始日とする。入社日が変更された場合、人事部は速やかに情報システム部へ通知する。

## 3. 契約社員・派遣社員
契約期間が人事システムまたは委託管理台帳に登録されていることを条件に発行する。申請には契約終了日、受入責任者、アクセス対象システムを明記する。有効期限は契約終了日の23時59分（日本時間）とし、契約更新が確定しても自動延長しない。受入責任者は契約終了日の3営業日前までに延長申請を行う。延長申請が承認されない場合、アカウントは予定どおり停止する。

## 4. 外部委託先アカウント
外部委託先には必要なシステムだけを許可し、原則として社内メール、ファイル共有、VPNを一括付与しない。発注部門の責任者が業務内容、委託期間、必要な権限を記載し、情報システム部の承認を得る。VPN権限が必要な場合は、理由と接続元を申請書に記載し、情報システム部長の追加承認を得る。委託契約終了日の当日18時にアカウントを停止する。契約終了日が休日の場合も停止時刻は変更せず、事前に必要な引継ぎを行う。

## 5. 停止条件
次のいずれかに該当した場合、情報システム部はアカウントを停止する。
- 退職・契約終了が人事部または委託管理責任者から通知された場合。
- 重大なセキュリティ事故または不正利用の疑いがあり、情報システム部長またはセキュリティ責任者が停止を指示した場合。
- MFA端末の紛失が報告され、本人確認済みの代替認証手段がない場合。
- 連続6回の認証失敗で自動ロックされた場合は、停止ではなく一時ロックとして扱う。本人確認後、ヘルプデスクが解除できる。
- 休職の場合は、休職開始日、職務、復職予定日を人事部が通知し、情報システム部がリスクに応じて停止または権限縮小を決める。休職だけを理由に一律停止しない。

## 6. 緊急時の停止
不正アクセスが継続している可能性がある場合、セキュリティ責任者は事後記録を条件として即時停止を指示できる。利用者や上長からの口頭連絡のみで恒久停止するのではなく、報告者、根拠、実施時刻を記録する。インシデント報告の期限や報告先は「05-incident.md」に従う。停止したアカウントの再開は、本人確認、原因確認、必要なパスワード変更、MFA確認を行い、停止を指示した責任者が承認する。

## 7. 権限付与と棚卸し
権限は業務上必要な最小限とする。管理者権限は期限を定め、上長と情報システム部長の承認を得る。権限の棚卸しは四半期ごとに実施し、上長は不要な権限を確認して削除を依頼する。アカウント発行や停止に関するFAQは「06-faq.md」に掲載されているが、条件の詳細は本基準を優先する。

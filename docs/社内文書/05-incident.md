# セキュリティ事故報告手順
文書番号：情手-SEC-011　版数：第3版　施行日：2026年7月1日
主管部署：セキュリティ管理室

## 1. 目的と対象
本手順は、情報漏えい、端末紛失、マルウェア感染の疑い、不審な認証要求、誤送信、アカウント不正利用、会社データの誤公開などを検知した際の報告と初動を定める。事故かどうか判断できない場合も、事故の疑いとして報告する。被害の確定を待ってはならない。

## 2. 報告期限と報告先
事故またはその疑いを認識した時点から、**30分以内**にセキュリティ窓口（内線7711、社内ポータル「セキュリティ事故速報」）へ第一報を行う。窓口に接続できない場合は、情報システム部当番責任者へ電話し、接続不能だった事実を記録する。第一報では、報告者、発生時刻または発見時刻、対象端末・アカウント、現象、実施済み対応、連絡可能な電話番号を伝える。
第一報後、**2時間以内**に直属上長へ報告し、業務影響と顧客・個人情報の有無を共有する。重大事故の可能性がある場合は、上長への報告を待たず第一報と同時にセキュリティ窓口へ緊急性を伝える。上長への報告だけでは正式な事故報告を完了したことにならない。

## 3. 初動対応
- PC紛失・盗難：最後に確認した場所と時刻を記録し、端末の遠隔ロックを依頼する。自分で端末追跡サービス等を追加インストールしない。
- 不審なMFA要求：承認せず、要求時刻と画面内容を記録し、セキュリティ窓口へ30分以内に報告する。
- マルウェア感染の疑い：ネットワークから切断する。ただし、電源を切る、ファイルを削除する、初期化する操作は、証跡保全の指示があるまで行わない。
- 誤送信・誤公開：可能であれば共有設定や送信先を変更して拡大を防ぎ、対象データを削除する前に窓口へ相談する。
- アカウント不正利用：安全に実行できる場合はセッションの切断を行い、パスワード変更やアカウント停止は窓口の指示に従う。ただし、情報システム部から即時停止指示があった場合はそれに従う。

## 4. 証跡と記録
メール、ログ、画面のスクリーンショット、時刻、表示されたエラーなどを可能な範囲で保存する。証跡を加工したり、SNSや個人クラウドへ転送したりしてはならない。報告時点で不明な項目は「不明」と伝え、後から判明した内容を追加する。原因を自己判断で断定せず、事実と推測を分けて記録する。

## 5. 報告後の対応
セキュリティ管理室は重大度を判定し、必要に応じて情報システム部へアカウント停止、端末隔離、ログ保全を依頼する。利用者は、調査終了まで対象端末の利用再開やデータ削除を独断で行わない。顧客や外部機関への連絡は、広報・法務等の指定責任者が行う。利用者が独自に外部へ説明してはならない。
